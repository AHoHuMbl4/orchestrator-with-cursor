# Специфика движков

## Claude Code

- Субагенты: инструмент Agent (в ранних версиях Task); headless-запуск оркестратора с субагентами —
  `claude --agents '{"имя":{"description":...,"prompt":...,"tools":[...],"model":"..."}}'`
  (или файлы `.claude/agents/*.md`).
- Вызов скилла: `/orchestration`.
- Headless `claude -p`: молчаливые отказы прав не меняют exit code — ловушка №9
  в `traps.md`.
- Модели/effort: алиасы default/best/sonnet/opus/haiku/fable;
  `--effort low|medium|high|xhigh|max`; бюджет прогона `--max-budget-usd`.

## Codex CLI

- Субагенты включены по умолчанию (built-in `default`/`worker`/`explorer`);
  кастомные — TOML в `~/.codex/agents/` или `.codex/agents/` (name,
  description, developer_instructions, model, model_reasoning_effort,
  sandbox_mode). Рычаг параллельности (аналог parallel_per_task) —
  `max_concurrent_threads_per_session` в `[agents]` (`~/.codex/config.toml`),
  там же дешёвая модель обёртки: `default_subagent_model`.
- Headless: `codex exec --sandbox workspace-write -a never`.
- Модели динамически: `codex debug models`. Вызов скилла: `$orchestration`.

## Kimi Code

- Субагенты: одиночные — инструмент Agent; залпы параллельных — AgentSwarm.
  Вызов скилла: `/skill:orchestration`; команды при занятом агенте встают в
  очередь, Ctrl-S — вклинить немедленно.
- Хуки: UserPromptSubmit может дописывать текст в контекст; SessionHeartbeat
  — observation-only (таймер решает «пора сверкиться», доставляет следующий
  UserPromptSubmit); PostToolUse — только наблюдение. Нудж сверки (10 мин)
  доставляется с следующим сообщением владельца (UserPromptSubmit) — во
  время одного длинного хода с фоновыми прогонами напоминаний НЕ будет,
  это нормально; контроль живости — логи прогонов и панель, а не нудж.

## Внешние исполнители (режимы: auto | local-cursor | cursor-cloud | subagents)

**Двойная схема.** Код-задачи → локальный cursor-agent CLI (`run-exec.py`);
не-код (исследования) → Cursor Cloud (`run-cloud.py`). Авто-маршрутизация
по домену роли: роль из `code/` → код. Явный `execution.executor` в params
перекрывает авто-выбор.

- **local-cursor** (код; отдельная квота Cursor): бинарник `cursor-agent` в
  PATH. Доктрина Cursor — «агент сам исследует кодовую базу»: локально у
  него есть ФС проекта, кураторство контекста в промте НЕ нужно. Лаунчер —
  **`run-exec.py`**: промт только из файла (`--prompt-file`), лог с
  `EXIT=<код>`, авто-retry при EXIT=4/124 (`execution.retry_on_fail`).
  Запуск: `run-exec.py --id <id> [--session <sid>] [--prompt-file P.md]`.
  Весь прогон — в `.orchestration/sessions/<sid>/runs/<id>/` (prompt.md,
  run.log, артефакты). Модель исполнителя всегда auto.
- **cursor-cloud** (не-код; отдельная квота Cursor): Cloud Agents API
  (`https://api.cursor.com`), ключ в **cursor.com/dashboard → API Keys**,
  файл `.orchestration/cursor.key` или env `CURSOR_API_KEY`. Чистый REST
  (curl/python-stdlib); нужны платный план, ключ и привязка GitHub.
  Поток: create → polling → artifacts. Создание `POST /v1/agents`,
  follow-up `POST /v1/agents/{id}/runs`, статус/результат `GET
  /v1/agents/{id}/runs/{runId}`. Результат — текст + git-ветка/PR.
  Тело create/follow-up: `"prompt": {"text": "..."}` (объект, не строка) —
  см. https://cursor.com/docs/cloud-agent/api/endpoints. Клиент кита —
  **`run-cloud.py`**: общие флаги `--id`/`--api-key` допустимы до и после
  субкоманды (`run-cloud.py --id w1 run --prompt-file P.md` и
  `run-cloud.py run --id w1 --prompt-file P.md`). Промт — только из файла
  (`--prompt-file`); приёмка по артефактам/`run-cloud.py status|artifacts`
  и логу, не по «словам» исполнителя. Подтверждено живьём: промты до
  ~77 КБ принимаются API; для больших пачек в синтез/критиков передавай
  ВЫЖИМКИ вердиктов (список проблем по схеме «ПРОБЛЕМА: место — суть —
  как чинить» + вердикты), а не полные тексты артефактов — экономит и
  квоту, и контекст. Выжимки — только с пометкой в промте критика
  («ВЫЖИМКИ полных артефактов…»); проверка новых фактов — только против
  полных входов (см. SKILL «Обрезка входов»). Детект исчерпания квоты (для
  `on_cursor_fail`): `429` + «Rate limit…» — временный лимит, подождать;
  «Usage limit exceeded»/spend limit — квота исчерпана, действовать по
  правилу скилла. `resource_exhausted` на create («Rate limit exceeded for
  creating cloud agent environments») — burst-лимит попыток: пауза ≥15–30 мин,
  одиночный повтор, при повторе — экспоненциальный рост паузы (ловушка №17
  в `traps.md`); 500 internal на create может маскировать тот же лимит.
  **Лимиты планов динамические.** Лимиты одновременных прогонов зависят от
  текущего плана Cursor и меняются при апгрейде/даунгрейде без правок кита;
  не зашивай названия тарифов и числа в промты/доктрину. При повторяющихся
  concurrency-отказах фиксируй наблюдаемый предел (N параллельно прошло,
  N+1 отказ) и докладывай владельцу — решение об апгрейде плана принимает
  владелец, не система.
  Ключ: `--api-key` > env `CURSOR_API_KEY` > `<state>/cursor.key`; сохранение
  через панель (абсолютный путь к ключу панель показывает после сохранения).
  Весь прогон — в
  `.orchestration/sessions/<sid>/runs/<id>/` (prompt.md, run.log, артефакты).
  **Протокол артефакта (cloud):** у облачного исполнителя нет нашей ФС — в
  промте облака НЕ требовать «запиши в файл-артефакт»; результат ЦЕЛИКОМ в
  финальном тексте ответа (включая таблицы/URL). Оркестратор сам сохраняет
  текст ответа run в `sessions/<sid>/runs/<id>/artifact.md`. Роль-шаблон
  «запиши в файл» — для локальных исполнителей (`run-exec.py` / субагенты).
- **auto** (дефолт): роль из `code/` → local-cursor (есть `cursor-agent`)
  иначе СТОП/лестница (НЕ cloud); не-код → cursor-cloud при ключе иначе
  СТОП/лестница. Никакого молчаливого fallback. Субагенты движка — только
  после явного «да» или `execution.executor = subagents`.
- **subagents** — субагенты движка оркестратора (расход его квоты); см. разделы
  Claude/Codex/Kimi выше.
- **Claude Managed Agents API** — облачные сессии без CLI; детали — по доке
  Anthropic на момент запуска.

## Код-задачи через облако (без репо) — fallback

**Fallback, когда локальный CLI недоступен; основной путь кода — локальный CLI
(`run-exec.py`).** Включается явно владельцем / params, не авто-выбором `auto`.

Облачный агент без подключённого репозитория не видит ФС проекта —
контекст отбирает оркестратор. Риск: неверный отбор → решение на
искажённом фундаменте. Протокол минимизирует этот риск.

- **Роли:** каскад домена `code/` как обычно (архитектор / кодер /
  тестировщик / ревьюер) — библиотека ролей та же.
- **Манифест:** оркестратор начинает с полного списка файлов задачи
  (дерево/`ls`) + точек входа и ВКЛАДЫВАЕТ его в промт целиком; агент
  видит карту кодовой базы, не слепые выдержки.
- **Фрагменты:** любой вложенный кусок кода помечен
  `ФРАГМЕНТ (файл:<путь>, строки <N–M>)` — агент знает, что видит часть.
- **Дозапрос контекста (multi-turn):** не хватает файлов — агент пишет
  `НЕ ХВАТАЕТ: файлы X, Y, Z` и НЕ начинает правки (стоп-точка).
  Оркестратор шлёт содержимое follow-up'ом (`run --agent-id`). Это НЕ
  ремонтный follow-up (тот — после критики по `ПРОБЛЕМА:`); дозапрос —
  только про недостающий контекст до правок.
- **Возврат:** unified-дифф или полные новые файлы — текстом (малое) или
  через artifacts API (большое). Оркестратор применяет ЛОКАЛЬНО (патч),
  гоняет тесты/сборку локально — приёмка только по замеру (тесты
  зелёные = готово). Протокол артефакта исследований (результат в тексте
  ответа → `artifact.md`) не противоречит: для кода текст/artifacts —
  носитель диффа, не замена локального замера.
- **Критики:** смотрят ПРИМЕНЁННЫЙ локальный дифф (не текст ответа
  агента) — обычная волна, критерий «тесты + логика».
- **Граница:** основной путь кода — локальный CLI (`run-exec.py`); режим
  без репо через облако — fallback при недоступности CLI. Для крупных баз
  cloud без репо — обходной путь; при подключённом репозитории облако само
  клонирует и исследует базу. Включается владельцем явно.

## Модели

Имена моделей и уровни effort не хардкодить: снимать с движков на месте
(`claude --help`, `codex debug models`) — списки меняются. Для local-cursor
модель исполнителя всегда auto; для cursor-cloud модель задаёт облако/API.
